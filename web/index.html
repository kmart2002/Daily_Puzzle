Toolchain

Professional Editing Tools

Every tool in this pipeline was chosen because its native project format is parseable — meaning editorial decisions can be extracted programmatically and turned into structured training data without guesswork.

🎬
Shotcut
Video

MLT-based open-source NLE with an XML project format that exposes every clip's in/out points, filter chain, and timeline position. Ideal for frame-accurate cut annotation and three-way color grading datasets.

  • MLT XML export
  • Three-way color grade
  • Frame-accurate trim
  • 60+ video filters
🎞
OpenShot
Video

Python-backed NLE with a native JSON project format — the most directly machine-readable of any NLE in this pipeline. Supports batch annotation extraction via the openshot Python library.

  • Native JSON format
  • Python API access
  • Transition library
  • Keyframe animation
📽
Lightworks
Video

Professional broadcast NLE used on major film productions. EDL (Edit Decision List) export provides frame-accurate cut-point data in an industry-standard format. Preferred for narrative and broadcast-style editing datasets.

  • EDL export
  • Broadcast-grade tools
  • Multi-cam support
  • 4K / 8K capable
🎹
LMMS
Audio

Open-source DAW combining a piano-roll sequencer, Beat+Bassline editor, and ZynAddSubFX synthesizer. MMP XML project files expose tempo, key, note data, and full FX chain configuration — essential for music generation training data.

  • MMP XML format
  • ZynAddSubFX synth
  • Beat+Bassline editor
  • LV2 plugin host
🎚
Ardour
Audio

Professional DAW built for demanding multi-track recording and post-production. Session XML captures full routing graphs, LV2/VST plugin chains, automation lanes, and region edits — the ground truth for voice and podcast training data.

  • Session XML format
  • Non-destructive editing
  • LV2/VST plugin chains
  • EBU R128 metering
🔌
LSP & Calf Plugins
Audio

Open-source LV2 plugin suites used across LMMS and Ardour sessions. Consistent parameter naming across projects makes cross-session effects-chain comparison meaningful — critical for training signal-processing models.

  • Parametric EQ
  • Multi-band compressor
  • De-esser
  • Noise gate + limiter
Process

The Annotation Workflow

Raw media files are not training data. The editorial decisions made during production — what to cut, where to cut it, why it was rejected — are the actual training signal. Here's how those decisions get captured and structured.

01
Ingest & Classify

Source media is catalogued with technical metadata: frame rate, resolution, codec, sample rate, bit depth. Each take gets a unique reference ID. Problem takes are flagged before editing begins — not after.

02
Edit in the NLE / DAW

Edits are made in the appropriate tool (Shotcut for rough cuts, OpenShot for color, LMMS for music composition, Ardour for voice). Every decision is made the way a professional editor would make it — not staged for the dataset.

03
Annotate the Decision

Each editorial decision is written to a JSON annotation file conforming to the schema. In/out points, transition types, color grade parameters, effects chains, and mix levels are all captured with exact values — no rounding, no estimates.

04
Quality Gate

Every annotation is rated 1-5. Only ratings ≥ 3 are eligible for accepted: true. Rejected annotations are kept in the dataset with a controlled-vocabulary rejection_reason — negative examples matter.

05
Schema Validation

All annotations are validated against the JSON Schema before commit. Required fields, enum constraints, type constraints, and conditional requirements (e.g., rejection_reason required when accepted: false) are all enforced programmatically.

06
Dataset Diversity Review

Before each batch commit, annotations are reviewed for diversity: tool distribution, edit type coverage, parameter value spread. A dataset where 80% of annotations are the same edit type is not useful training data — gaps are filled before delivery.
